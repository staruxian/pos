# CLAUDE.md

POS (касса) для магазина одежды «Shaxzoda Premium». React 19 + Vite SPA, Bun-сервер,
Turso (libSQL) как база. Деплой на Vercel.

## Команды

```bash
bun run dev          # сервер (:3001) + Vite (:5173) параллельно
bun run dev:server   # только API, bun --watch server/index.ts
bun run dev:client   # только фронтенд
bun run build        # vite build -> dist/
bun run start        # прод-сервер
```

Тестов и линтера в проекте нет. Проверка типов — `bunx tsc --noEmit`.

## Архитектура

- `server/auth.ts` — вход по общему паролю магазина и подписанная сессия в cookie.
- `server/security.ts` — разбор `__path`, лимит размера тела, счётчик запросов, CSPRNG.
- `server/index.ts` — весь API. Один экспорт `handle(req)`: плоская цепочка
  `if (method === ... && pathname === ...)` без роутера. Ответы — через хелперы
  `json()` / `error()`. `fetchApi()` оборачивает `handle` в CORS и `try/catch`.
  Запускает `Bun.serve` только под `import.meta.main`.
- `api/index.ts` — тонкая обёртка для Vercel Functions, экспортирует `{ fetch: fetchApi }`.
- `server/db.ts` — клиент libSQL, схема (`CREATE TABLE IF NOT EXISTS` + ручные
  `ALTER TABLE` для добавленных колонок), обёртка `db.query(sql).all/get/run(...args)`
  в стиле `bun:sqlite`, и `withTransaction(tx => ...)`. Все вызовы ждут `dbReady`.
- `src/lib/api.ts` — типы доменных сущностей и объект `api` с методами `fetch`.
  Единая распаковка ответа в `parse<T>()`.
- `src/App.tsx` — layout + вкладки, держит список товаров в состоянии и раздаёт его
  страницам через `useOutletContext`. Роуты объявлены в `src/main.tsx`.
- `src/pages/*.tsx` — четыре экрана: Касса, Товары, Клиенты, Отчёты.
- `src/components/ui/*` — shadcn/ui (new-york, base color neutral), алиас `@/*` → `src/*`.

Таблицы: `products`, `sales`, `sale_items` (с денормализованными `product_name`/`sku`),
`clients`, `client_ledger` (`kind` = `debt` | `payment`). Баланс клиента нигде не хранится —
он всегда считается суммой по `client_ledger`.

## Вход и сессии

Аутентификации по пользователям нет — есть один пароль магазина (`POS_PASSWORD`).
`POST /api/login` проверяет его за постоянное время и выдаёт cookie `pos_session`:
HttpOnly, SameSite=Strict, срок 12 часов, подпись HMAC-SHA256 на `SESSION_SECRET`.
Токен самодостаточен, в базе ничего не хранится; смена `SESSION_SECRET` завершает
все сессии.

Публичны только `/api/health`, `/api/login`, `/api/logout` и `/api/session` —
всё остальное отвечает 401 без сессии. Список в `publicPaths`; **новый маршрут
закрыт по умолчанию**, специально ничего делать не нужно.

На клиенте `parse()` в `src/lib/api.ts` на 401 бросает `UnauthorizedError` и шлёт
событие `pos:unauthorized`; `App` ловит его и показывает `LoginPage`.

CORS намеренно отсутствует: фронтенд и API живут на одном origin (в разработке —
через прокси Vite), поэтому чужим сайтам обращаться сюда незачем.

## Деньги — целые тийины, не дробные сумы

`price`, `total`, `unit_price` и `amount` хранятся и передаются целым числом
тийинов (1/100 сума). Конвертация только на границе с формами: `toMinor()` при
отправке, `fromMinor()` для заполнения поля, `money()` для вывода (все в
`src/lib/utils.ts`). Сервер требует целое число и отвергает дробное.

Старые базы переводит одноразовая миграция `money-minor-units-v1` в `server/db.ts`:
она умножает суммы на 100 и ставит отметку в таблице `meta` в той же транзакции.
Повторно не сработает, но **необратима** — перед первым деплоем сделайте дамп базы.

## На Vercel все `/api/*` переписываются в одну функцию

`vercel.json` переписывает `/api/:path*` → `/api?__path=/api/:path*`, поэтому
`handle()` берёт путь из `url.searchParams.get("__path") ?? url.pathname`.
Новые роуты пишите от полного пути `/api/...`, иначе в проде они не найдутся.
Второй rewrite отдаёт `index.html` всему, что не `/api`, — для SPA-роутинга.

`__path` подконтролен клиенту, поэтому `resolvePath()` доверяет ему только когда
запрос пришёл на `/api` и значение — корректный путь `/api/...`. Иначе фильтр по
пути на уровне платформы (Deployment Protection, WAF) обходился бы через `?__path=`.

## Печать этикеток

Печать идёт не из браузера, а через локальный мост к Xprinter (`src/lib/printer.ts`,
`VITE_PRINT_URL`, по умолчанию `http://localhost:5000/print`). Мост принимает
`{ data, text }` и сам формирует этикетку 60 × 30 мм. Сервер отдельно рендерит
SVG-штрихкод Code 128 через `bwip-js` на `GET /api/products/:id/barcode` — это только
для предпросмотра в диалоге, печать через него не идёт.

Мост подставляет подпись в шаблон команд принтера, поэтому `printLabel()` вырезает
из названия управляющие символы, кавычки и слеши и обрезает строку до 64 символов.
Сам мост живёт вне этого репозитория: его CORS должен быть ограничен origin кассы,
иначе печатать сможет любой открытый в браузере сайт.

## Соглашения

- Язык интерфейса и текстов ошибок — русский. Все сообщения пользователю пишите по-русски;
  комментарии в коде тоже русские, и их немного — только там, где неочевидно «почему».
- Валидация целиком на сервере, ответ — `error("Сообщение", status)`. Клиент показывает
  `err.message` как есть.
- Ошибки БД не глушим: `catch` ловит только `isUniqueViolation(e)`, остальное летит
  наверх и логируется как 500. Иначе сбой соединения выглядел бы как дубликат штрихкода.
- Штрихкод (`sku`) — только цифры; при создании товара без него генерируется 12-значный
  в `newBarcode()`.
- Суммы форматируются `money()` из `src/lib/utils.ts` (локаль `ru-RU`).
- Даты хранятся строкой `datetime('now', 'localtime')`, сравнения по диапазону — строковые.

## Окружение

`.env` (не в git) должен задавать `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`,
`POS_PASSWORD` и `SESSION_SECRET` (не короче 32 символов) — без них `server/db.ts`
и `server/auth.ts` падают на старте, и это правильно: касса не должна подниматься
без пароля. Образец — `.env.example`.

Заголовки безопасности (CSP, nosniff, HSTS, frame-ancestors) заданы в `vercel.json`
и действуют только в проде. `connect-src` в CSP перечисляет адрес моста печати —
при смене `VITE_PRINT_URL` обновите и его.
